# 实施计划
## Phase 0 基线（P0）
确认分支、依赖、测试、Windows 构建流程；用已授权账号对真实投稿接口做匿名/登录对比，检查单视频、多P、批量下载、抖音及订阅回归；记录限制。未实测不得标记通过。
## Phase 1 闭环（P0）
在 BiliFetchPage 增加主页模式，复用 biliFetchSpace；列表摘要映射现有状态，选中后补齐详情/分P，复用下载入队；加错误提示及测试。第一版保留100上限。
## Phase 2 分页（P0）
新增单页接口与真实 next_page，前端加载更多、排序、筛选、取消、去重；测试重复页、空页、动态变化及失败恢复。
## Phase 3 B站集合（P1）
分别验证合集/系列/公开收藏夹接口，再接入统一摘要；不默认支持私人收藏。
## Phase 4 主页（P1）
恢复手动采集、保留订阅模式；复用 B站采集组件，增加抖音手动采集并验证订阅兼容。B站订阅独立启用。
## Phase 5 混合批量（P1）
按链接分流，保留部分成功、导入与图文功能。
## Phase 6 下载增强（P2）
目录规则、历史、元数据、API；先核对已有能力。
## Phase 7 扩展（P2）
TikTok 可行性和维护评估后实施，不阻塞前面阶段。

每阶段独立提交、测试并更新验收记录；不合并 master，未验证项明确标记。

## 强制开发约束
仅在 codex-dev 增量开发；保留 Tauri 2、React/TypeScript、FastAPI、SQLite 和现有主题、悬浮导航、Hero、下载队列。不得擅自重构 UI、替换技术栈或引入 Redis、PostgreSQL、Docker 等额外运行依赖。保持 Windows 原生打包、原有接口和数据兼容；凭据不得进入日志、提交或导出。仅处理有权访问及下载的内容。
